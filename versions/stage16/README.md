# Wormfront Armageddon — 16단계 음량 조절·저장

게임 오른쪽 위의 음량 버튼을 열어 배경음악과 효과음을 각각 0~100%로 조절합니다. 조절 값은 기존 설정과 함께 저장되며 다음 접속에도 유지됩니다. 0%는 무음이며 ON/OFF 상태와 독립적입니다. 슬라이더 키보드 조작은 게임 이동·발사 입력으로 전달하지 않습니다. 이전 실행 파일 94개는 versions/stage15에 보존했습니다.

## 15단계 배경음악

사용자가 제공한 Bouncy Tactical Groove.mp3를 기본 음량 18%로 재생합니다. 효과음 발생 시 음악을 잠시 45% 수준으로 줄이고 복원합니다. 끝과 시작 0.5초를 겹쳐 반복 지점을 부드럽게 연결합니다. 음악 ON/OFF와 일시정지·복귀, 탭 숨김·복귀를 지원하며 단일 HTML에도 음악을 포함합니다. 원본 MP3는 변경하지 않았고 이전 실행 파일 90개를 versions/stage14에 보존했습니다.


GitHub Pages에서 실행할 수 있는 정적 웹 게임입니다. 배포에는 `index.html`, `src/`, `styles/`, `assets/`를 함께 유지합니다. 외부 서버, API 키, 설치형 라이브러리가 필요하지 않습니다.

## 유지된 9단계 맵 테마

햇살 해안, 폐허 도시, 사막 협곡, 군사 해안, 초록 언덕, 오로라 설원, 고철 야적장, 용암 성채, 달 기지, 노을 섬의 10개 테마를 시작 화면에서 선택합니다. 선택한 맵의 배경을 미리 보여 주고 브라우저 설정에 저장합니다. 배경·지형·수면 색은 테마에 맞춰 바뀌며 중력·수위 상승·지형 파괴 규칙은 같습니다. 달은 저중력 모드가 아니며 용암도 기존 물과 같은 접촉 사망 규칙을 사용합니다.

제공한 나머지 화면 예시 9장을 참고해 UI와 캐릭터 없는 배경을 built-in imagegen으로 제작했습니다. 저장 경로와 프롬프트 전체는 assets/THEME_PROMPTS.json에 있습니다. 새 테마 배경은 선택할 때만 로딩하며 실패 시 해당 테마의 절차적 색상 표시를 사용합니다. 원본 PNG와 8단계 전체 56개 파일은 versions/stage8/에 보존하고 해시를 확인했습니다.

release/wormfront-stage16-pages.zip에는 61개 실행 파일이 있습니다. 이미지 30장 합계와 단일 HTML 크기는 검수 보고서에 기록합니다. 단일 HTML은 모든 테마를 포함하여 파일 크기가 더 큽니다.

## 유지된 8단계 시각 개선

제공한 ZIP의 캐릭터 10종과 아이템 10종을 원본 PNG 그대로 적용했습니다. 팀별 외형 선택과 저장, 무기 아이콘, 수류탄·다이너마이트·지뢰·양 폭탄 표시를 연결했습니다. 배경 예시 10장은 참고 자료로 보존했으며, 해안 예시를 참고하여 UI 없는 배경 한 장을 imagegen으로 제작했습니다. 제작 프롬프트와 도구 모드는 assets/BACKGROUND_PROMPT.txt에 있습니다.

흙·잔디 지형, 금속 느낌의 패널과 선택 표시를 적용했습니다. 단일 캐릭터 이미지에 이동·점프·피격 변환을 적용하며 별도의 프레임 애니메이션은 포함하지 않습니다. 나머지 무기 9종은 기존 벡터 아이콘을 사용합니다. 이미지가 로딩되지 않으면 기존 벡터·절차적 화면으로 대체합니다.

원본과 이전 수정본은 original/ 및 versions/에 보존했습니다. 7단계 전체 파일은 versions/stage7/에 있습니다. 8단계 배포 ZIP은 release/wormfront-stage8-pages.zip에 유지했습니다. 당시 40개 파일의 명세는 versions/stage8/release/manifest.json에 보존했습니다. 당시 PNG 합계는 약 22.3 MB, 단일 HTML은 약 34 MB입니다.

## 유지된 CPU 개선

CPU는 지형·거더·낙차·지뢰·다른 캐릭터를 확인하고 최대 75/130/180픽셀(쉬움/보통/어려움)의 안전한 보행 위치를 선택합니다. 가까운 적과의 거리, 낮은 체력일 때 체력 상자, 지뢰 위험을 평가합니다. 이동은 실제 고정 간격 물리를 사용하며 최대 3.5초 후 사격으로 넘어갑니다.

배트는 근접 적에게 사용하고 로켓·수류탄·유도탄은 공유 탄도로 후보를 평가합니다. 예상 적 피해와 처치 보너스에서 아군 피해·거리·한정 탄약 비용을 뺍니다. 안전한 후보가 없으면 턴을 넘깁니다. 난이도에 따라 탐색 간격과 조준 오차가 달라집니다. CPU의 로프·제트팩·점프 경로 탐색과 모든 무기의 전술 사용은 아직 포함하지 않습니다.

무기 피해·반경은 src/weapons.js의 weaponBalance에서 관리합니다. 분열탄 자탄 피해를 낮추고 바나나탄·공습 초기 탄약을 각각 1개로 제한했습니다. 자세한 전후 수치는 검수 보고서에 있습니다. 체감 밸런스는 추가 플레이로 조정할 수 있습니다.

5단계 전체 파일은 versions/stage5/에, 단일 파일은 dist/wormfront-stage5-offline.html에 보존했습니다.

## 유지된 5단계 변경

- 5단계의 벡터 캐릭터·무기와 절차적 배경은 8단계 이미지 로딩 실패 시 대체 표시로 유지합니다.
- 6단계 가이드에서 이동·발사·카메라·로프·제트팩·턴 규칙을 안내합니다. 열면 전투를 정지하고 닫으면 이전 정지 상태를 복원합니다. 실습 미션은 포함하지 않습니다.
- 팀 이름·대전 옵션·음악·효과음과 가이드 완료 상태를 저장합니다.
- 최근 30경기의 승자·체력·생존자·턴·전투 시간을 저장합니다. JSON 내보내기와 두 번 확인하는 기록 삭제를 지원합니다.

저장 키는 wormfront.settings.v1, wormfront.results.v1, wormfront.guide.v1입니다. 현재 브라우저의 localStorage에만 저장하며 기기 간 동기화하지 않습니다. 저장이 차단되면 현재 화면에서만 유지합니다. 손상된 JSON은 자동으로 덮어쓰지 않습니다. file:// 저장 범위는 브라우저와 파일 위치에 따라 달라질 수 있습니다.

4단계 전체 분리본은 versions/stage4/에, 단일 HTML은 dist/wormfront-stage4-offline.html에 보존했습니다. build-offline.cjs는 HTML 버전 표시를 읽어 현재 9단계 파일을 생성합니다.

분리된 코드를 수정한 뒤 다음 명령으로 현재 소스가 포함된 단일 HTML을 다시 생성할 수 있습니다.

```powershell
node scripts/build-offline.cjs
```

## 3단계 변경 범위

- 드래그로 카메라 이동, 휠·버튼·두 손가락으로 확대/축소, 전체 맵 보기와 웜 추적.
- 확대/축소 후에도 같은 월드 좌표를 조준할 수 있도록 화면 좌표 변환 적용.
- 목표 무기 사용 중 드래그·핀치하면 발사하지 않고 카메라만 조작.
- 320×568, 390×844 세로 화면에서도 조작 버튼과 무기 목록이 겹치지 않도록 배치.
- 모바일 제트팩 상승·하강, 로프 길이 조절, 턴 넘김 버튼.
- 여러 손가락 동시 입력, 포인터 캡처, 취소 시 충전 발사 방지.
- 로프의 길이 제한과 접선 속도, 길이 조절, 고정점 파괴 시 해제.
- 웜·제트팩·로프의 이동 경로와 지형·거더 충돌 검사.
- 점프 후 0.33초 이내 두 번째 입력으로 백플립. 세 번째 입력은 추가 점프를 만들지 않음.
- 피격 및 로프 해제 속도가 보행 속도에 제한되지 않도록 수정.

### 조작

키보드 A/D 이동, W 점프·두 번 백플립, 위/아래 조준, Space 충전·발사 또는 로프 해제, Enter 턴 넘김, Escape 정지/재개. 로프는 W/S 길이, 제트팩은 W/S 상승·하강입니다.

카메라: 화면 드래그, 휠 또는 +/− 확대·축소, M 전체 맵, C 웜 추적. 드래그 이후 카메라는 그 위치를 유지하며 웜 추적 버튼/C로 복귀합니다.

모바일: 이동·점프·조준·발사 버튼과 상승/하강·로프 길이·턴 넘김 버튼을 사용합니다. 발사는 누르고 충전한 뒤 손을 떼면 나갑니다. 화면 드래그와 두 손가락 확대·축소, 전체 맵·웜 추적 버튼을 사용할 수 있습니다. 아래 무기 목록은 좌우로 스크롤할 수 있습니다.

## 유지된 2단계 변경

- 충돌용 `Uint8Array`를 사용해 이동·투사체·CPU 계산에서 개별 Canvas 픽셀 읽기를 제거.
- 맵 생성 시 전체 충돌 배열 생성, 폭발·드릴 사용 시 변경한 영역만 갱신.
- 초당 60번의 고정 간격으로 물리, 전투 시간, 파티클과 폭발 효과 처리.
- 화면 갱신 속도와 물리 처리 속도 분리. 긴 프레임의 따라잡기는 최대 0.25초로 제한.
- CPU 예측과 실제 투사체에서 초기 속도, 중력, 바람, 신관, 튕김, 거더·웜·물·경계 충돌 규칙 공유.
- 투사체 경로를 최대 2픽셀 간격으로 검사해 얇은 지형 관통 방지.
- CPU 예측 함수는 실제 지형, 탄약, 체력, 투사체 목록을 변경하지 않음.

`scripts/build-stage1.cjs`부터 `scripts/build-stage4.cjs`까지는 보관된 이전 단계에서 해당 단계 수정본을 생성합니다. 파일을 덮어쓰므로 후속 변경이 있는 상태에서 실행하기 전 확인해야 합니다. 4단계 생성기는 `src/`, CSS와 오프라인 출력도 다시 생성합니다.

## 검수

현재 보고서는 `verification/stage16/REPORT.md`입니다. 회귀·저장·CPU·배포본·이미지·테마 및 새 전투 표시·병합 기능 검사 결과는 개별 JSON과 보고서에 기록했습니다. 모바일은 브라우저 에뮬레이션으로 확인했으며 실제 기기 검사는 포함하지 않습니다.

이전 단계 검수 결과와 스크린샷은 `verification/stage1/`, `verification/stage2/`, `verification/stage3/`에 보관했습니다.

`scripts/verify-browser.cjs`는 Playwright와 설치된 Microsoft Edge를 사용합니다. 게임 실행에는 Playwright가 필요하지 않습니다. 검사용 내부 접근 코드는 임시 HTTP 응답에만 삽입되며 배포 파일에는 들어 있지 않습니다.
